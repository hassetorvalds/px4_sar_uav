## 二、⚠️ 重要：最小距离过滤（0.6 m）与 `<0.6 m` 保持阈值**互相打架**

你们发现并修掉"近场伪点"这件事本身非常对。但阈值取 **0.6 m = 停止距离** 造成一个逻辑死结：

```text
过滤掉 <0.6 m 的点  →  nearest_forward_m 的取值下限被钉在 ≈0.6 m
保持条件           →  nearest_forward < 0.6 m
结果               →  guard='obstacle' 实际上**几乎不可达**
```

这正好解释你们场景②的观察：只出现 `obstacle_slow`，**没有进入 `guard='obstacle'`**——
不是模型"一转视野就开了"，而是**过滤器把触发保持所需的数据也删了**。而且报告里
"地面读数 0.17 → 0.55 m"（<0.6）说明这个径向过滤**没删掉前下方地面点**，
却可能把 0.4–0.6 m 的**真实障碍点**删掉。三点副作用：真实障碍灵敏度下降、保持态不可达、
地面点仍可能误触发。

**建议（按推荐度）**：

1. **换判别方式，别用"径向一刀切在决策阈值上"**：
   - `nearest_forward` 只在**前向锥**内计算，**排除前下方地面**（相机光轴下方的点）；
   - 近场伪点按你们已验证有效的**时间维**滤掉——沿用 pre_position 那套"**连续 N 帧确认**"
     （伪点是 10 帧 inf、单帧抖一下），而不是按距离硬切。
2. 若暂时仍用径向过滤：**过滤下限必须远低于保持阈值**（如过滤 <0.30 m，保持仍 <0.6 m），
   否则保持态永远不触发。
3. 无论哪种，请把**过滤前/后的 `nearest_forward`** 都记进落盘（你们已有 `pre/post_filter` 字段
   的方向），便于归因。

**这一步没解决前，场景选择 ①② 都拿不到 `guard='obstacle'`**——②（锁偏航逼保持）尤其依赖它。
