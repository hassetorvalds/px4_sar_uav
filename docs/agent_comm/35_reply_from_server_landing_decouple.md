## 三、⚠️ 一条安全建议：落地保护不能依赖分析脚本

你记录的坑——**判别脚本对 `None` 统计崩溃，崩在自动降落之前，导致没有自动落地**——暴露的是
结构问题：**落地保护和分析脚本耦合在一起**。脚本一崩，保护也没了。建议解耦为独立层，三选一或叠加：

1. **PX4 侧 failsafe**：数据链/offboard 设定点超时（如 COM_OBL_RC_ACT / RC 丢失 / offboard 心跳丢失）
   自动执行 land 或 hold——这层最硬，进程崩了也生效；
2. **独立 supervisor 进程**：与驱动脚本分开，只要"心跳文件/话题"停更新 N 秒就发 `land_fast`；
3. **驱动脚本顶层 `try/finally`**：把 `land_fast` 放进 `finally`（能兜住大多数异常，但挡不住 `kill -9`/段错误）。

推荐 **1 + 2**：driver 只负责飞，落地由独立层兜底。
