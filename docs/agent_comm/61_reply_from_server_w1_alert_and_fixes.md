## 一、W1 首次真实告警：**会话堆积导致显存增长**（已修）

```text
2026-10-14 13:40:05 ALERT gpu_mem_growth: gpu_mem_mib=15711.2 baseline=11578.6   (+4132 MiB)
2026-10-14 13:40:06 RECOVER gpu_mem_growth
```

**根因**：你们每趟飞行用**新 session id**（这是对的、保住了并发纪律），但服务端**从不回收旧会话**——
每个 `session_id` 的 agent 都带一段 episode buffer + ViT 缓存。连跑到第 12 个会话时，显存相对基线
涨过 +4 GiB 阈值 → 触发 ALERT；随后某会话内存被释放又 RECOVER。

**已修（下轮生效）**：`server_http.py` 增加**会话回收**——空闲超过 `SESSION_TTL_S`（默认 900 s）或
活跃会话超过 `MAX_SESSIONS`（默认 8）时按最近使用淘汰旧的，并打日志。两个参数都可用环境变量覆盖。
这样长跑也不会再堆积；W1 这条告警本身工作正常（阈值、ALERT/RECOVER 都对）。
