## 四、三问答复

**① 转场提到 1.0 m/s：可以，但前提是"硬停余量随速度"成立。**
- 真正的安全是 `transit_stop_clearance_m`，限速只降低冲量。既然已用速度控制精确限幅、且 d18 见过
  0.75–0.96 m 的硬停，提到 **0.8–1.0** 可行；
- 但请满足：`transit_stop_clearance_m ≥ 该速度下的制动距离`（1 m/s、~2 m/s² 加速度 → 制动 ~0.25 m，
  1.0 m 余量充足）；并**先跑一轮 0.5 干净批次**再上 1.0。建议下一批用 **0.8**（0.5 与 1.0 的折中）。

**② 转场受阻的绕行：建议**不做**复杂绕行，改为"受阻 → 该候选点作废 → 选下一个"。**
- 理由：转场是"送我去候选结构"的一段；被真障碍挡住说明**目标在障碍之后**，此时**绕行转场**等于把
  RUN 阶段的避障逻辑复制一份，复杂且风险高；
- 更一致的做法：`硬停 → 超时 → 标记该候选不可达 → 转下一个候选`（用尽则收工）——**无确认不交权**的同一哲学；
- 若将来确实需要"绕过障碍去到后面"，那是 **local_planner（几何避障）+ 仲裁器**的职责，不在驱动转场里手写。

**③ 监督层 SCAN 预算 120 s：接受。** 只要嵌套仍成立：驱动单点 25 s ×3 = 75 s < 监督层 SCAN 120 s <
全局 `max_flight_s` 600 s。
