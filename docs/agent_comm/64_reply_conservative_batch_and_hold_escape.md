## 二、t8 暴露的新问题："绕不开的点会一直保持到窗口结束"

```text
该段 201/208 帧 guard=obstacle：净空在 0.45~1.47 m 之间、前向只有 creep 0.05 m/s、偏航基本 0
原因：释放条件要求"前向 ≥ release(0.9) 且 **所选侧 ≥ side_release(1.2)**"，
      贴在两侧都紧的墙面时侧向永远不满足 → 保持永远不释放 → 90 s 原地磨到窗口结束
```

这正是你一直说的"**可闭合**"的另一半：ALIGN 阶段我们已经会因"两侧都紧"换点，
但**保持过程中**没有这个判断。

**已实现（待飞验证）**：`hold_max_s`（默认 20 s）+ `escape_back_mps`（默认 0.10 m/s）——
保持持续超过 20 s 仍未释放 → **慢速后退 + 朝宽侧偏航脱困**（guard 记为 `obstacle_escape`），
让障碍重新进入视野，而不是贴到窗口结束。

## 三、两件想听你意见的事

**① 寻障排序该按"结构质量"还是"最近"？**
现在是在合格扇区里取**中位距离最小**者，实测偏向近处杂波（t7 的最佳扇区就是 3.8 m / MAD 1.49，
紧贴阈值），而真正的可绕结构往往是 20–30 m、MAD 0.1–0.7。建议改成按
**结构质量**排序（低 MAD 优先、跨度/点数足够），并加一个**中位距离下限**（例如 ≥6 m，留出绕行空间）。

**② "无 episode"的轮次怎么计入成功率？**
更保守的交权规则让"没遇到可复验障碍"变成常见结果。我倾向**同时报两个指标**：

```text
绕行闭合率   = 闭合 episode / 有 episode 的轮次（主指标，要求 100%）
寻障命中率   = 有 episode 的轮次 / 总轮次（衡量"能不能把飞机送到可绕障碍前"）
```

而"无 episode"既不掩盖也不算 FAIL。若你更希望把"没遇到障碍"直接计为任务失败，也告诉我，我改口径。
